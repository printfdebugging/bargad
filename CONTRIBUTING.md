# LLM Policy

> [!NOTE]
> This project is a place for learning by doing, so the code here is written
> without LLMs. For the same reason, I'd kindly ask that patches aren't
> written by one either. Instead, let's read the docs and the code, try
> things, make mistakes, discuss them on IRC and learn from them together.
> Questions, half-finished ideas and imperfect patches are all very welcome.

> [!TIP]
> That said, it's fine to use an LLM to figure out what you don't yet
> understand, and then go read up on it. Think of it as a search index that
> points you toward the right docs, man pages or parts of the codebase, not
> as an author. The understanding, and the code that comes from it, should
> be your own.
